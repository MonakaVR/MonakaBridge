# RenderModel identification update and axis preparation

The user requested the supplied identification model update followed by physical rotation checks. The old `pico_motion_tracker` resource stays intact for regression and rollback. The updated production resource is `pico_tracker_rev3_identification`; the separate instrumented resource is `pico_tracker_rev3_axis_debug`.

The presentation selector accepts only these three exact names. Each model has its own compiled manifest digest and contained OBJ/MTL/PNG files. Unknown models, missing or modified assets, unapproved mappings, and identity conflicts retain the existing fail-closed presentation behavior. No resource name changes pose conversion, tracking validity, calibration, World, Mount or approval. Selection is an immutable Provider initialization snapshot; restore uses a new snapshot, not a tracking reset or a new logical identity.

The supplied OBJ uses one unique UV index per face corner (94,014 expanded corners). Exact duplicate UV coordinates are compacted to 147 entries and 49,103 expanded vertices, within the OpenVR uint16 index range. Ordered face vertex/normal indices and sampled UV coordinates are retained. The 2,048 square production atlas is byte identical to the supplied PNG. The prior deployed mesh has 31,305 triangles; the supplied high precision mesh has 31,338. The earlier export dropped 33 triangles collapsed by six-decimal quantization. All high precision geometry is preserved under the HIL-confirmed rigid rotation described below, without moving the model origin.

Diagnostic arrows extend from 18 to 66 mm along final resource-local positive X/Y/Z. Separate colored, double-sided labels identify the axes and physical features. The diagnostic atlas contains the supplied image unchanged in its upper half; original UVs map to that half. The underlying corrected body is identical to the updated production mesh. Face and USB cards follow the body's rotation; axis arrows/cards stay on the final coordinate axes so their labels remain true.

Naming is explicit: source OBJ directions are logo -Y, back +Y, LED/button/arrow -Z, USB -X. Corrected resource directions are logo -Z, back +Z, LED/button/arrow +Y, USB -X. The requested diagnostic text `+Z / FORWARD` names positive local Z; it does **not** change OpenVR's right-handed +X right, +Y up, -Z forward convention. `TOP: BACK +Z` retains the prepared model's back-face name, not physical up. None of these labels implies a tracking quaternion change.

Physical HIL on source `5370068b208c703c41e70d87ea91241c198c9378` confirmed a fixed model-local offset. The operator held logo up, LED away, USB right: the USB/pink direction agreed while the green +Y arrow pointed toward the real LED. An initial capture with uncertain timing was retained but excluded; repeated neutral and pitch plus yaw and roll each had 60/60 valid poses and 17/17 fresh source snapshots. The operator confirmed matching physical/model rotation directions. Measured pitch/yaw/roll axes were near -X/-Z/+Y, with residuals 4.28/5.10/7.26 degrees. Together these identify the nominal correction `Rx(+90 degrees)`, `(x,y,z) -> (x,-z,y)`; this is not a sub-degree fit.

HIL ended before the correction was implemented. `assets/pico-rev3-identification-source/axis-hil-correction-evidence.json` pins the observations and raw result hashes. Only body vertices/normals and attached physical-feature cards receive the exact signed permutation. No translation, scaling, face reordering, Pose/World/Mount/approval/profile/backend changes occur. The old `pico_motion_tracker` resource is unchanged. Corrected physical alignment remains NOT_RUN until a separate axis-only retest; offline tests do not close that gate.

Offline validation retains all 41 RenderModel cases and existing regression cases. Additional cases exercise both new selections, asynchronous/synchronous activation, initial hidden recovery, repeated hide/reacquire, corrupt resources, and restoring production selection on the same package. Asset tests invert the confirmed rotation to verify exact original geometry/normals, face order and sampled UVs, and reject both missing and reversed corrections. They also verify contained material/texture, PNG decoding/CRC, winding, finite vectors, bounds and expanded vertex limits. Mock results are not physical display claims.
