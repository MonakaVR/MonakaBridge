# RenderModel identification update and axis preparation

The user requested the supplied identification model update followed by physical rotation checks. The old `pico_motion_tracker` resource stays intact for regression and rollback. The updated production resource is `pico_tracker_rev3_identification`; the separate instrumented resource is `pico_tracker_rev3_axis_debug`.

The presentation selector accepts only these three exact names. Each model has its own compiled manifest digest and contained OBJ/MTL/PNG files. Unknown models, missing or modified assets, unapproved mappings, and identity conflicts retain the existing fail-closed presentation behavior. No resource name changes pose conversion, tracking validity, calibration, World, Mount or approval. Selection is an immutable Provider initialization snapshot; restore uses a new snapshot, not a tracking reset or a new logical identity.

The supplied OBJ uses one unique UV index per face corner (94,014 expanded corners). Exact duplicate UV coordinates are compacted to 147 entries and 49,103 expanded vertices, within the OpenVR uint16 index range. All supplied vertex and normal records, ordered face vertex/normal indices, and sampled UV coordinates are retained. The 2,048 square production atlas is byte identical to the supplied PNG. The prior deployed mesh has 31,305 triangles; the supplied high precision mesh has 31,338. The earlier export dropped 33 triangles collapsed by six-decimal quantization. This import preserves the supplied higher precision geometry and does not infer a new origin or rotation.

Diagnostic arrows extend from 18 to 66 mm along positive local X/Y/Z. Separate colored, double-sided labels identify the axes and physical features. The diagnostic atlas contains the supplied image unchanged in its upper half; original UVs map to that half. The underlying body is identical to the updated production mesh. No correction matrix is applied.

Naming is explicit: the supplied README calls the logo face FRONT (-Y), back +Y, LED/button/arrow -Z, USB -X. The requested diagnostic text `+Z / FORWARD` names positive local Z; it does **not** change OpenVR's right-handed +X right, +Y up, -Z forward convention. `TOP: BACK +Y` identifies a model-local surface, not a verified physical tracking axis. These labels must not be used to infer tracker quaternion corrections.

Physical HIL remains necessary. Record a neutral physical reference and independent pitch/yaw/roll observations, then either confirm alignment or record the exact model-local offset. Never alter software during the physical measurement sequence. No fixed offset is assumed from the provisional CAD conversion.

Offline validation retains all 41 RenderModel cases and existing regression cases. Additional cases exercise both new selections, asynchronous/synchronous activation, initial hidden recovery, repeated hide/reacquire, corrupt resources, and restoring production selection on the same package. Asset tests verify lossless UV compaction, original geometry, single contained material/texture, PNG decoding/CRC, winding, finite vectors, and expanded vertex limits.
